# Выпуск версии

CD здесь — публикация проверенных файлов прошивки в GitHub Releases. Прошивка
физической платы автоматически не выполняется.

## Подготовка

1. Изменить исходники и обновить раздел Unreleased в `CHANGELOG.md`.
2. Запустить `make docker-build`, проверить `out/ci/reports/summary.md`.
3. Для версии, предназначенной пользователям платы, выполнить
   [аппаратную проверку](hardware-validation.md). QEMU её не заменяет.
4. Перенести изменения из Unreleased в раздел версии с датой, закоммитить и
   отправить изменения в основную ветку. Дождаться успешного workflow.
5. Создать аннотированный тег на проверенном commit и отправить его:

```sh
# Пример; выбрать номер очередной версии проекта.
git tag -a v0.1.0 -m "Release v0.1.0"
git push origin v0.1.0
```

Эти команды не выполняются автоматически при редактировании проекта. Тег является
явным сигналом для публикации. Для пробного выпуска используйте `v0.1.0-rc.1`.

## Что делает workflow

Тег запускает полную сборку и тесты в Docker. Release job скачивает артефакт
того же запуска, проверяет SHA256 и commit в `build-info.json`, затем создаёт
GitHub Release с BIN, HEX, ELF, MAP, метаданными и контрольными суммами.
Заметки генерируются GitHub; подробная история изменений находится в CHANGELOG.

Release job не пересобирает прошивку, не меняет тег и не перезаписывает уже
существующий Release. Повторный запуск после успешной публикации завершится
ошибкой создания существующего Release — это предохраняет выпущенные файлы от
незаметной замены. Исправления выпускайте новым номером версии. Если публикация
прервалась частично, проверьте состояние Release и assets перед ручным исправлением.

## Настройки репозитория

- Включить GitHub Actions. Организационная политика должна разрешать release job
  запрашивать `contents: write` у стандартного `GITHUB_TOKEN`.
- Для основной ветки рекомендуется branch protection с обязательной проверкой
  `Docker / native / QEMU / firmware`.
- Ограничить создание и изменение тегов `v*` участниками, выпускающими версии.
- Публикация из PR и ручного workflow_dispatch отключена условием release job.

Настройки GitHub/branch protection workflow не меняет. Их задаёт владелец репозитория.

## Проверка загруженных файлов

Скачайте assets в одну папку и выполните:

```sh
sha256sum --check SHA256SUMS       # Linux
shasum -a 256 --check SHA256SUMS   # macOS
```

BIN прошивается по адресу `0x08000000`; ELF содержит символы для отладки.
Перед прошивкой проверьте совместимость платы и тактирования в README.
