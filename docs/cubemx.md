# Повторная генерация CubeMX

В `stm32_sump_analyzer.ioc` уже включено `ProjectManager.KeepUserCode=true`.
Все новые подключения в `Src/` и `Inc/` находятся в `USER CODE BEGIN/END`.

- `main.c`: include, инициализация в SysInit, приоритет USB в секции 2,
  `analyzer_board_poll()` внутри пользовательского участка WHILE.
- `stm32f4xx_it.c`: include и переходники обработчиков в секции 1.
- `usbd_cdc_if.c`: include, callbacks 3/4/6/7, вспомогательные функции в
  PRIVATE_FUNCTIONS_IMPLEMENTATION.
- `usbd_desc.c`: общий заголовок идентификации в INCLUDE; переопределения
  строк USB в PRIVATE_DEFINES. Имя устройства сохраняется после генерации.
- Заголовки: declarations/includes внутри соответствующих пользовательских секций.

В исходном `usbd_cdc_if.c` был повреждён комментарий `USER CODE END INCLUDE`.
Он восстановлен: иначе CubeMX не мог бы надёжно сохранить этот участок. Это
единственное исправление самого маркера; остальной генерируемый текст сохранён.
В исходном main уже есть `__WFI()` вне USER CODE; новая логика от него не зависит,
поэтому удаление этой старой строки при генерации не нарушит работу приложения.

Новые каталоги `core/`, `platform/`, `tests/`, `qemu/` и `GNUmakefile` вручную
поддерживаются отдельно. Обычный `make` использует `GNUmakefile`, а не перезаписанный
CubeMX Makefile. Проект проверен с существующей раскладкой `Src/Inc` и библиотеками
STM32Cube FW_F4 V1.24.2. Обновление CubeMX/HAL до иной структуры каталогов требует
отдельной проверки сборки и USB API.

```sh
make check-cubemx
```

Проверка удаляет содержимое USER CODE из 15 файлов и сравнивает остальной текст
с SHA256 исходной версии. Также проверяется парность маркеров. Тест не запускает
CubeMX и не является доказательством работы произвольной будущей версии генератора.
После намеренной регенерации отличия в генерируемом тексте нужно просмотреть и
только затем обновить соответствующие значения в `tests/cubemx_generated.sha256.json`.
Не следует автоматически обновлять эталон в обычной проверке — это скрыло бы ошибку.

Не назначайте CubeMX те же TIM1/TIM8/DMA/EXTI обработчики: ими владеет адаптер.
Если переносите настройку этих ресурсов в `.ioc`, сначала удалите или перенесите
соответствующие переходники в созданные CubeMX USER CODE секции, чтобы не получить
дубли определений. Для повторной генерации текущего `.ioc` это не требуется.
