# Работа над проектом

## Быстрый старт

```sh
git clone https://github.com/ALLeksandrOrlov/stm32-sump-analyzer.git
cd stm32-sump-analyzer
make docker-build
```

Нужны Git, GNU make и работающий Docker с Buildx. ARM toolchain и QEMU устанавливать
на компьютер не требуется. Результаты находятся в `out/ci/dist`, отчёты —
в `out/ci/reports`. На macOS Docker использует Linux VM (Docker Desktop или Lima).

## Где менять код

- `core/sump_protocol.*`: только wire protocol и метаданные.
- `core/capture.*`: конфигурация, ECA-контроллер, чтение кольца.
- `core/analyzer_app.*`: связь команд, контроллера и транспорта.
- `platform/stm32/`: регистры, IRQ, USB mailbox и сборка компонентов.
- `Src/`, `Inc/`: только секции `USER CODE`; см. [правила CubeMX](docs/cubemx.md).
- `qemu/`: отдельная модель нужной периферии, не продуктовая прошивка.

Ядро должно оставаться C11 без HAL/USB include и динамического выделения памяти.
ISR должны быть короткими: никакого ожидания USB или обработки протокола.
Сохраняйте контракт владения TX-буфером до завершения передачи.

## Проверка изменений

Для быстрой итерации с установленным C-компилятором: `make test test-sanitize`.
Перед отправкой изменений: `make docker-build`. Изменение регистров/IRQ должно
проверяться интеграционными тестами в расширенном QEMU. Изменение модели QEMU
проверяется против того же драйвера STM32 и должно сопровождаться описанием
поддержанного поведения и ограничений.

В PR укажите:

- какую проблему решает изменение и как меняется поведение;
- какие проверки выполнены;
- есть ли изменения wire protocol, таймингов или совместимости платы;
- какие проверки ещё требуют реального устройства.

Не добавляйте новые артефакты в исторический каталог `build/`. Новые результаты
сборки хранятся в игнорируемом `out/`. Не обновляйте эталон CubeMX автоматически,
чтобы случайные изменения генерируемого кода не становились «разрешёнными».
