# Проверка SUMP через последовательный порт

`sump_smoke.py` работает на Linux/macOS с Python 3 и стандартной библиотекой.
Сначала прошейте плату и закройте PulseView и другие программы, использующие порт.
Порт указывается явно: скрипт не ищет и не открывает другие устройства.

```sh
python3 tools/hardware/sump_smoke.py \
  --port /dev/cu.usbmodemXXXX \
  --board 'STM32F407 board identifier' \
  --firmware-commit '<commit actually flashed>'
```

Для Linux используйте путь своего устройства, например `/dev/ttyACM0`.
Не копируйте пример имени порта без проверки. Скрипт задаёт serial 115200 8N1,
не выполняет явных операций с DTR/RTS, не прошивает устройство и не управляет
GPIO как выходами. Захват использует обычную конфигурацию входов прошивки.
Внешний генератор не нужен: значения отсчётов могут быть любыми.

Проверяются:

- `1ALS`, имя устройства, версия прошивки, восемь каналов, 28 672 байта памяти
  и заявленный предел 20 МГц в метаданных;
- ровно 4, 68, 1024 и 28 672 отсчёта при запрошенных 100 кГц без триггера;
- десять повторных RUN, следующий сразу после получения последнего отсчёта;
- команды в отдельных записях и несколько команд в одной записи, RESET после
  незавершённой команды и потребление аргументов неизвестной длинной команды;
- отказ RUN при отключённой группе входов или превышении памяти, ответы ID
  в состоянии ошибки и восстановление захвата после RESET.

Разбиение записей на реальные USB-пакеты определяет драйвер ОС; этот тест не
утверждает, что каждый отдельный байт создаёт отдельный USB-пакет.
После проверки скрипт отправляет RESET; при ошибке также пытается остановить
захват. Ошибка или таймаут дают ненулевой код завершения.

Каждый запуск создаёт новый каталог `out/hardware/<UTC time>/`:

- `report.json`: результаты, настройки и указанные оператором сведения о плате;
- `tx.bin`, `rx.bin`: полный записанный обмен, включая данные перед ошибкой;
- `capture-*.bin`, `repeat-*.bin` и другие `.bin`: полученные отсчёты, по одному
  байту на отсчёт в порядке выдачи SUMP, от новых к старым.

`--output` задаёт другой **новый** каталог. `--timeout` задаёт бюджет ответа
(по умолчанию 3 секунды; время накопления отсчётов учитывается отдельно),
`--repeat` — число повторных запусков, `--sample-rate` — частоту 1 кГц…1 МГц.
Фактический период на плате и пропускная способность этим сценарием не измеряются.
Проверки фронтов, порядка сигнала, USB-переподключения и предельной частоты описаны
в [инструкции для платы](../../docs/hardware-validation.md).

Тесты самого скрипта не обращаются к аппаратуре:

```sh
python3 -m unittest discover -s tests -p test_hardware_smoke.py
```

Полный сценарий также можно запустить против
[PTY-устройства PulseView](../pulseview/sump_fixture.c), указав
`--port /tmp/stm32-sump-analyzer`. Такой результат проверяет host-сценарий и
переносимое ядро; он не является результатом испытания STM32 или USB.
